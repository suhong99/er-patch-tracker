# 신규 실험체 자동 등록

## 개요

- **시작일**: 2026-02-06
- **상태**: 완료
- **관련 브랜치**: feature/57

## 문제점

현재 `parse-balance-changes.ts`에 `VALID_CHARACTERS`가 하드코딩되어 있음:

- 신규 실험체 추가 시 코드 수정 + 배포 필요
- 관리자 페이지에서 관리 불가
- 깜빡하면 데이터 유실

## 목표

- [x] 크롤링 시 "신규 실험체 - XXX" 패턴 감지하여 자동 등록
- [x] DB 기반 캐릭터 목록 필터링으로 전환
- [x] `VALID_CHARACTERS` 하드코딩 제거

## 설계

### 패치노트 구조

```html
<h5>신규 실험체 - 펜리르</h5>
<!-- 신규 캐릭터 소개 -->

<h5>실험체</h5>
<!-- 기존 캐릭터 밸런스 패치 -->
```

### 변경 흐름

```
크롤링 시작
    ↓
h5 태그 순회
    ↓
"신규 실험체 - XXX" 패턴 발견?
    ↓ YES
DB characters 컬렉션에 신규 캐릭터 등록
    ↓
기존 파싱 로직 진행 (DB 기반 필터링)
```

### 변경 파일

- `scripts/parse-balance-changes.ts` - 메인 로직 수정
- `scripts/crawl-patch-notes.ts` - 신규 실험체 감지 로직 추가 (선택)

## 진행 상황

### 2026-02-06

#### 1. 현재 구조 분석

- `VALID_CHARACTERS`: 85개 캐릭터 하드코딩 (76~162줄)
- `isValidCharacter()`: 화이트리스트 체크 (172~174줄)
- 필터링: 파싱 후 화이트리스트에 없으면 제거 (847줄)

#### 2. 구현 완료

**변경 사항:**

1. `VALID_CHARACTERS` 하드코딩 제거 → `validCharacters` (DB에서 로드)
2. `SECTION_TITLES` 블랙리스트 추가 (섹션 제목 필터링)
3. `loadValidCharacters()` 함수 추가 - Firestore에서 캐릭터 목록 로드
4. `extractNewCharacterFromH5()` 함수 추가 - "신규 실험체 - XXX" 패턴 추출
5. `registerNewCharacter()` 함수 추가 - 신규 캐릭터 DB 등록
6. `detectAndRegisterNewCharacters()` 함수 추가 - 패치노트 스캔 및 등록
7. main 함수 수정 - 파싱 전 신규 실험체 감지 단계 추가

**테스트 결과:**

```
=== 테스트 모드 ===
DB에서 85개 캐릭터 목록 로드됨
  ✨ 신규 실험체 "펜리르" DB 등록 완료
신규 실험체 감지: 펜리르
```
